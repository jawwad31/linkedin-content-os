# Angle Types

Use exactly one primary angle:

| ID | Required movement |
|---|---|
| `diagnostic` | symptom → likely root cause → how to check |
| `myth_correction` | common belief → why incomplete → better belief |
| `framework` | model → parts → application |
| `checklist` | decision → criteria → action |
| `process_breakdown` | stages → handoffs → failure point |
| `before_after` | documented weak state → strong state → bridge |
| `mistake_lesson` | documented mistake → consequence → operating rule |
| `objection_handling` | buyer concern → reality → safer next step |
| `cost_of_inaction` | delay → compounding consequence → decision point |
| `decision_criteria` | what to evaluate → what to ignore → selection rule |
| `comparison` | approach A → approach B → when each fits |
| `case_example` | sourced scenario → constraint → lesson |
| `trend_take` | market shift → ICP implication → founder POV |
| `operator_pov` | direct belief → reasoning → practical consequence |
| `faq_answer` | buyer question → clear answer → nuance |

`mistake_lesson`, `before_after`, and `case_example` require event support.
`trend_take` is usually strongest for TrendCards and Trend Reactions. Never
force an angle that requires evidence the source does not provide.
