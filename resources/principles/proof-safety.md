# Proof-Safety

Proof-safety means never inventing evidence. The system may shape approved proof, but it must not create proof that was not supplied.

## Never Invent

- Revenue numbers
- Pipeline numbers
- Conversion rates
- Client results
- Founder stories
- Customer quotes
- Screenshots or testimonials
- Market statistics
- Research conclusions
- Named customers
- Timeframes
- Team size
- Product capabilities

## Allowed

- Use approved proof supplied in business context or the current request.
- Use cautious phrasing when evidence is directional, such as "many teams see" only when the user has provided support.
- Use qualitative operator observations when clearly framed as perspective, not fact.
- Replace unsupported claims with practical reasoning.

## If Proof Is Missing

Choose one:

1. Remove the unsupported claim.
2. Rewrite it as a question or hypothesis.
3. Use a placeholder only if the user explicitly asked for a draft with placeholders.
4. Ask for approved proof if the claim is central.
5. Flag the gap in proof notes.

## Proof Notes

Proof notes should state:

- What proof was used.
- What proof was avoided.
- What proof is missing.
- Whether any claim needs user approval before publishing.
